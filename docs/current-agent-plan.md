更新时间：2026-06-29

## 目标

把 `E:\PPT工具` 做成围绕两套 Skill 的本地 PPT Agent：

```text
上传 PPT / PDF / 图片 / brief
-> codex-ppt 生成视觉统一的图片型 PPT
-> image-to-editable-ppt / editppt 重建为对象级可编辑 PPT
-> 质量检查、人工复核、失败恢复、交付门禁
-> 下载 editable-final.pptx
```

旧模板、旧设计方向和旧本地一键生成器不能回到主流程，只能作为高级诊断或兼容提示。

## 后续执行顺序

1. **新文件泛化测试**
   - 用另一个 PPT 或 PDF 跑一轮小样本。
   - 先跑 1 到 2 页，不静默消耗全量 API 额度。
   - 验证不是只适配当前 15 页样例。

2. **普通用户前端继续收口**
   - 首页只保留用户能理解的阶段、阻断原因、下一步和最终文件状态。
   - worker、manifest、hash、artifact、provider 默认进入高级详情。
   - 旧模板、旧设计方向、旧一键生成器不显示在主流程。

3. **单页失败恢复**
   - 失败原因：对话模型无响应、JSON 不可解析、额度不足、鉴权失败、PowerPoint 打开失败、页面证据过期、整页截图风险。
   - 影响页面：明确列出页码。
   - 推荐动作：重置页面、重跑页面、重新合成 final。
   - 已成功页面不能被失败页污染。

4. **人工复核体验**
   - 逐页展示 `codex-ppt` 目标图、可编辑 PPT 预览图、页面校验结果、资产分离总览图。
   - 用户确认后记录人工复核。
   - 复核状态直接影响交付门禁。

5. **文档与运行手册**
   - README、产品目标、当前计划保持纯中文、无乱码、不过期。
   - 明确外部 API 调用必须显式确认。
   - 明确当前 15 页样例已 ready，下一阶段重点是泛化测试和体验收口。

## 不要做

- 不要恢复旧模板主入口。
- 不要用 passthrough 或 dry-run 冒充产品级结果。
- 不要绕过交付门禁直接开放最终下载。
- 不要在用户未确认额度前自动跑全量外部 API。
- 不要把 `codex-ppt` 和 `image-to-editable-ppt` 的核心契约改成新的平行流程。
