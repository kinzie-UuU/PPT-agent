# PPT Agent 前端 V2 架构

更新时间：2026-08-04

## 目标

新版前端是面向普通用户的 Agent 工作台，不再把 worker、manifest、hash、provider 和调试日志平铺在首页。主界面只回答五件事：当前任务是什么、做到哪一步、当前页面长什么样、下一步能做什么、文件能否下载。

## 当前结构

```text
src/main.jsx
  读取现有工作流状态、调用现有 API、执行已有动作
        |
        v
src/ui-v2/PptAgentWorkspace.jsx
  任务列表 / 页面画布 / Agent 进度 / 交付入口 / 新建任务
        |
        v
src/ui-v2/PptAgentWorkspace.module.css
  V2 独立视觉和响应式规则
```

- `src/main.jsx` 暂时作为控制器和兼容层，不改变双 Skill 的服务端契约。
- `PptAgentWorkspace` 是纯展示与交互外壳，只消费整理后的任务、预览、动作和交付数据。
- V2 样式使用 CSS Module，避免继续污染旧版全局样式。
- 默认进入 V2；`?ui=legacy` 是迁移期兼容工作台，不是历史界面的像素级快照。
- 兼容工作台不加载 V2 动态分包，可在 V2 模块加载失败时独立打开现有任务和流程动作。
- 外部图片 API、可编辑重建和全量运行仍沿用现有显式确认门禁。

## 产品信息架构

1. 左侧：任务记录、搜索、状态筛选、新建任务。
2. 中间：图片版或可编辑版页面预览、翻页、缩略图、逐页复核。
3. 右侧：Agent 当前动作、五阶段进度、图片版与可编辑版交付物。
4. 高级详情：归档任务、provider、worker、artifact、validation 和诊断能力。

## 保持不变

- `codex-ppt` 负责视觉统一图片型 PPT。
- `image-to-editable-ppt / editppt` 负责对象级可编辑重建。
- `gpt-image-2` 外部调用必须显式确认。
- blocked、draft、ready 的交付门禁不被 UI 绕过。
- 旧模板、旧设计方向和旧本地一键生成器不回到主流程。

## 后续拆分

1. 从 `src/main.jsx` 提取统一的工作流视图模型，避免页面组件重复理解服务端状态。
2. 把长流程动作整理为明确状态机：待确认、运行中、可恢复、待复核、可交付。
3. 把任务列表和任务详情改为可寻址路由，刷新页面后仍能回到当前任务。
4. 为页面级重跑、批次进度和人工复核增加组件级测试。
5. V2 稳定后删除兼容工作台，而不是长期维护两套主界面。

## 完成标准

- 桌面和手机端无横向溢出、遮挡或不可读文本。
- 真实任务能显示页面、缩略图、翻页、进度和交付状态。
- 新建任务只要求上传材料、说明需求和选择交付目标。
- 高级详情默认折叠。
- `npm.cmd run check`、`npm.cmd run regression:skill-first`、`npm.cmd run build`、`npm.cmd run smoke` 全部通过。
