## 目标

把 `E:\PPT工具` 做成围绕两套 Skill 的本地 PPT Agent：

```text
上传 PPT / PDF / 图片 / brief
-> codex-ppt 生成视觉统一的图片型 PPT
-> image-to-editable-ppt / editppt 重建为对象级可编辑 PPT
-> 质量检查、人工复核、失败恢复、交付门禁
-> 下载 editable-final.pptx
```

旧模板、旧设计方向和旧本地一键生成器不能回到主流程，只能作为高级诊断或兼容提示。

## 后续执行顺序

1. **下一步编排收口**
   - `/next` 在 2/15 final 状态下不能只说“没有动作”。
   - 应明确提供“复核当前 2 页样例”和“继续生成剩余 13 页”两个选择。

2. **人工视觉复核闭环**
   - 交付区展示目标图、可编辑预览、页面校验和资产分离结果。
   - 用户确认后记录人工复核。
   - 复核通过后，当前 2 页可作为小样本结果下载，但必须继续提示完整产品交付需要覆盖 15/15 页。

3. **单页重跑与失败恢复**
   - 失败页可以单独重置、重跑、记录和重新合成 final。
   - 重跑前必须提示外部 API 调用，尤其是 `gpt-image-2` 和页面规格模型。
   - 已成功页面不能被失败页污染。

4. **15 页产品级验收**
   - 全量真实运行 `codex-ppt`，不能用 passthrough 或 dry-run 冒充。
   - 分批运行 `image-to-editable-ppt`。
   - 失败页单独重跑。
   - 合成 15 页 `editable-final.pptx`。
   - 交付门禁通过后，更新验收报告为 `acceptance.ready=true`。

5. **文档和前端体验清理**
   - 文档保持纯中文、无乱码。
   - 首页只展示用户能理解的阶段、阻断原因、下一步和最终文件状态。
   - worker、manifest、hash、artifact、provider 等细节默认进入高级详情。

## 不要做

- 不要恢复旧模板主入口。
- 不要用 passthrough/dry-run 结果冒充产品级结果。
- 不要绕过交付门禁直接开放最终下载。
- 不要在未确认额度前自动跑全量外部 API。
